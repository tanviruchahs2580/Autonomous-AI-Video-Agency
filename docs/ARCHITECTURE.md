# Architecture

## System overview

```text
Client / CLI
      ↓
FastAPI Control Plane (auth, RBAC, rate limit, idempotency)
      ↓
Master Orchestrator (agency/workflow/engine.py)
  Understand → Plan → Delegate → Execute → Verify → Repair → Deliver
      ↓
Durable Workflow Engine (DB-backed job/task state machine)
      ↓
Specialized Stage Handlers (agency/agents/stages.py)
      ↓
Capability Layer (agency/capabilities/*)
  media · tts · asr · captions · editing · graphics · router
      ↓
Tool Adapter Layer (FFmpeg, edge-tts, Pillow, provider HTTP adapters)
      ↓
Storage (local object store; S3-compatible interface) + Database (SQLite/PostgreSQL via SQLAlchemy)
```

## Design rules

1. **Capability-first, tool-second.** Interfaces (`TTSProvider`, `Transcriber`, `ObjectStore`, `ModelCandidate`) are permanent; implementations are swappable adapters.
2. **No uncontrolled LLM chains.** The orchestrator is deterministic. LLMs are optional providers behind the model router (script generation); every path has a deterministic fallback.
3. **Every artifact has provenance.** `artifacts.provenance_json` records origin/tool/license for each file.
4. **Every workflow is observable.** Structured JSON logs + `events` + `audit_logs` tables; every job traceable request→task→artifact→render→QA→delivery.
5. **Every critical workflow is recoverable.** Jobs survive restarts via DB state + heartbeats; stale running jobs are reclaimable; repairs are classified and bounded.

## Audio/video alignment strategy

Narration is generated by us, so the synthesis timeline is authoritative:

1. Storyboard distributes the target duration across scenes proportional to narration length.
2. After silence cleanup, scene clip durations are re-scaled so total video duration equals cleaned narration duration exactly.
3. Captions use absolute word timings from the same timeline — burned-in and sidecar stay in sync.
4. AV mux verifies drift < 1.5 s before proceeding; technical QA re-verifies stream sync.

## Failure handling

See [QA_AND_REPAIR.md](QA_AND_REPAIR.md). Summary: stage-level retries with backoff for transient classes; pipeline-repair strategies restart from the responsible stage (loudness→audio_mix, duration→editorial, sync→mux, corruption→assets); bounded repair budget; human escalation to `awaiting_approval` when exhausted.

## Scaling path

- Workers are stateless claimers — run N worker processes against a shared DB.
- PostgreSQL: set `AGENCY_DB_URL` to a Postgres DSN (SQLAlchemy dialect switch).
- GPU generative providers plug in via ComfyUI adapter point (`AGENCY_COMFYUI_URL`) with health checks through the model router.
- Object storage: `LocalObjectStore` implements the `ObjectStore` interface; an S3 implementation drops in without touching pipeline code.
